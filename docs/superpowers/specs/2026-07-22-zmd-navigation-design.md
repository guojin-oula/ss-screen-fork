# ZMD 工作区导航设计

## 目标

在仓库根目录新增 `ZMD/`，把当前真实工作区组织成一个面向研究人员和 AI 助手的路径导航知识库。ZMD 只保存目录职责、真实相对路径、入口文件、阅读顺序、关联测试/文档和同步记录，不复制正式源码，不移动或重命名现有文件。

## 核心原则

1. `AGENTS.md` 是每次工作的第一入口，`ZMD/README.md` 是文件定位的第二入口。
2. `src/`、`tests/`、`docs/`、`references/` 等真实目录仍是内容权威来源；ZMD 只是索引层。
3. ZMD 一级目录按知识功能组织，二级页面映射到真实目录和具体文件。
4. 所有链接使用仓库相对路径；WSL 绝对根路径只在总入口中记录。
5. 不移动、不删除、不复制现有研究资料。缓存、虚拟环境和 Git 内部文件不进入资产索引。
6. 新增、删除、移动、重命名或修改真实文件后，同一工作会话必须更新对应 ZMD 页面；即使职责未改变，也要更新同步记录。

## 信息架构

```text
ZMD/
├── README.md
├── 00_总览与使用规则/
├── 01_项目入口与配置/
├── 02_正式源码/
├── 03_测试与测试数据/
├── 04_项目文档与开发计划/
├── 05_历史科研资料/
├── 06_脚本与自动化/
└── 07_版本与变更索引/
```

`02_正式源码/` 进一步按 `data`、`pair`、`stability` 和 `cli` 拆分页面，确保可以从功能定位到具体 Python 文件。历史资料不逐份复制摘要，而是索引每个研究家族的目录、README、notebook/source/revisions 位置以及用途。

## 强制工作流

1. 阅读 `AGENTS.md`。
2. 激活 `.venv` 并验证 Python/`ss-screen`。
3. 阅读 `ZMD/README.md`。
4. 在对应 ZMD 分区找到真实路径、关联测试和文档。
5. 阅读真实文件后再修改。
6. 同步更新对应 ZMD 页面及 `07_版本与变更索引/README.md`。
7. 检查 Markdown 相对链接、目录树和真实文件系统的一致性。
8. 更新 `docs/PROJECT_LOG.md`。

## 更新规则

| 真实工作区变化 | ZMD 动作 |
|---|---|
| 新增文件/目录 | 在对应分区登记路径、职责和阅读位置 |
| 删除文件/目录 | 删除失效索引，不恢复用户已删除内容 |
| 移动或重命名 | 更新所有相关链接、目录树和资产索引 |
| 接口、职责或状态变化 | 更新说明、关联测试、实现状态和阅读顺序 |
| 普通内容修改 | 更新对应页面的同步记录 |
| 用户手动调整目录 | 重新扫描当前文件系统，以真实状态覆盖旧导航 |

## 验收标准

- 新读者只读 `ZMD/README.md` 就能理解项目区和推荐阅读顺序。
- 正式源码、测试、项目文档、历史资料、脚本和 CI 都有明确入口。
- 重要文件可以从 ZMD 通过相对链接直接定位。
- ZMD 不引用不存在的真实路径。
- `AGENTS.md` 明确规定先读 ZMD、修改后同步 ZMD。
- `git diff --check`、完整测试和 Ruff 检查通过。
