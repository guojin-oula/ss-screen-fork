# ZMD 同步更新规则

ZMD 必须与当前真实文件系统保持一致。任何真实文件变化都需要在同一工作会话检查并同步导航。

## 更新矩阵

| 变化 | 必须执行的导航动作 |
|---|---|
| 新增文件或目录 | 在对应分区添加路径、职责、关联测试/文档和阅读位置 |
| 删除文件或目录 | 删除对应索引与链接，不恢复用户已经删除的内容 |
| 移动或重命名 | 更新总目录树、资产索引、分区页和所有交叉链接 |
| 函数、CLI、数据格式或职责变化 | 更新功能说明、入口、输出和关联关系 |
| 测试增加或覆盖范围变化 | 更新测试映射和验证说明 |
| 项目状态或路线变化 | 更新文档导航与版本变更索引 |
| 只修改内部实现 | 核对职责描述；即使描述无需变化，也在变更索引登记已同步 |

## 每次工作检查清单

1. 已阅读 [`AGENTS.md`](../../AGENTS.md)。
2. 已激活 `.venv`。
3. 已从 [ZMD 总入口](../README.md) 定位目标。
4. 已阅读对应导航页和真实文件。
5. 已同步新增、删除、移动、职责和状态变化。
6. 已更新 [`07_版本与变更索引/README.md`](../07_版本与变更索引/README.md)。
7. 已检查 ZMD 内相对链接存在。
8. 已运行适用测试和格式检查。
9. 已更新 [`docs/PROJECT_LOG.md`](../../docs/PROJECT_LOG.md)。

## 路径规则

- 导航链接使用仓库相对路径，不重复写 WSL 绝对路径。
- 路径必须指向当前真实文件或目录，禁止提前索引尚未实现的文件。
- 示例路径必须明确标为示例，不能与真实资产表混放。
- 缓存、虚拟环境、`.git/` 和生成文件不属于 ZMD 资产。

## 信息冲突处理

当 ZMD 与真实工作区冲突时：

1. 以当前文件系统为准；
2. 不恢复用户已删除内容；
3. 修正失效导航；
4. 在变更索引记录原因和日期；
5. 如果冲突涉及项目范围，再同步 `PROJECT_LOG.md` 或 `PROJECT_PLAN.md`。
